# The command layer

The interface talks to the engine through one function: a command name and JSON arguments in, JSON or an error out. The desktop app calls it directly through Tauri. For testing in a headless browser, `prismqda serve` (built with `--features dev-server`) offers the same commands over `POST http://127.0.0.1:4891/rpc` with a body of `{"cmd": "...", "args": {...}}`. It answers `{"ok": true, "result": ...}` or `{"ok": false, "error": {"code": "...", "message": "..."}}`.

The code is in `crates/prismqda-api/src/lib.rs` and its tests in `crates/prismqda-api/tests/api.rs` show every command in use.

## Offsets

Every offset (`start`, `end`) counts **Unicode scalar values** (code points) into the source's text, which is stored in Unicode NFC. `start` is inclusive and `end` is exclusive. JavaScript strings count UTF-16 code units, so a character such as an emoji is one unit here and two in JavaScript. The interface must convert at the boundary and must be tested with text that contains characters above U+FFFF.

## Errors

`code` is stable. The ones the interface should handle:

| code | meaning |
|---|---|
| `no_project` | no project is open |
| `invalid` | the request broke a rule; `message` says which, in plain words |
| `not_found` | something the request named does not exist |
| `read_only` | the project was made by a newer version and cannot be changed |
| `exclusive_group` | a coding was refused because its code shares a mutually exclusive group with a code the same coder already gave to overlapping words; the message names the group and the code, and the same `coding.apply` with `replace_exclusive: true` takes the other coding away and applies this one |
| `duplicate` | the file was already imported |
| `bad_file` / `unsupported_file` | the file is damaged, or of a kind that cannot be imported |
| `bad_args` | the interface sent the wrong shape; this is a bug |
| `io`, `database`, `already_exists`, `not_a_project` | file problems |

### The launcher: recent files and sample projects
None of these needs a project to be open.

| command | arguments | result |
|---|---|---|
| `file.stat` | `path` | `{exists, is_file, name, modified, size}` |
| `text.read` | `path` | `{name, text, bytes, encoding}` |
| `text.write` | `path`, `text`, `replace` (optional, false) | `{path, bytes}` |
| `sample.list` | | `[{id, name, description, documents, codes, codings}]` |
| `sample.create` | `id`, `path` | project info, exactly as `project.create` returns it, including `sample_id` |

`file.stat` only asks the file system. It never opens the file as a project, so nothing is read from it, no backup is made, and no `-wal` or `-shm` file appears beside it. `name` is the last part of the path (also when nothing is there). `modified` is when the file last changed, in UTC with milliseconds in the form the project file uses, for example `2026-11-04T15:30:00.123Z`; it is `null` when nothing is there. `size` is in bytes, and 0 for a folder or a missing path. A path that does not exist is a normal answer, `{exists: false, is_file: false, name, modified: null, size: 0}`, not an error. A folder is `exists: true, is_file: false`. An empty `path` is `invalid`; any other failure of the file system, such as no permission, is `io`.

`text.read` and `text.write` read and write one small text file with no project open; the window uses them for the translation files a person brings in and the files it writes for a translator. `path` must be a full path (a relative one is `invalid`, and says what to type). `text.read` takes files up to 16 MB and understands UTF-8, UTF-8 with a byte-order mark, UTF-16 (with its mark), and Windows-1252 when the bytes are not UTF-8; `encoding` is `utf-8`, `utf-16`, or `windows-1252`, so the window can warn that accents may be wrong. A path that is not a file, or that cannot be read, is `invalid` or `io`; a file over the limit is `too_large`. `text.write` writes the text as UTF-8 (up to 32 MB), refuses a path whose folder does not exist, and refuses a file that is already there unless `replace` is true (the window sets it only after Windows' own save dialog has asked about replacing).

`sample.list` lists the sample projects that are built into the program. `documents` counts the texts, `codes` counts every code including the ones that group others, and `codings` counts the coded passages. `sample.draw` (under Reliability) is a different command.

`sample.create` makes a new, editable project at `path` from the sample named by `id`, and makes it the open project. As with `project.create`, the caller gives the path its `.pqda` ending. The copy is an ordinary project:

- Each document is imported as plain text, the way a `.txt` file is, so it has the same units, and is filed in the folder the sample names.
- The cases hold the documents the sample puts in them. The codebook has the sample's colors and definitions, with siblings in the order the sample lists them.
- Every coding belongs to the person using the project (`me`) and covers exactly the words the sample quotes. Notes are kept as the coding's note, ratings as its rating, and memos as memos about that coding.
- It starts a fresh session, so `undo` has nothing to undo until the person changes something.
- `sample_id` remembers which sample it came from. It is written into the project's creation event (the `project.create` event carries a `sample_id` key), so it needs no new table and the project format stays at 2. It cannot change, and it does not make the project special in any other way.
- The bundled original exists only inside the program, so it can never be changed. Making another copy always gives the sample as shipped, and two copies share nothing.

Errors: an `id` that is not a bundled sample is `not_found`; a `path` that already exists is `already_exists` and the file there is left alone; an empty `path` is `invalid`; a folder that does not exist is `database`. The copy is all or nothing. If anything fails, no file is left behind (including SQLite's `-wal` and `-shm`), and the project that was open stays open. A sample whose quoted words cannot be found, or are found more than once, in their document is `invalid` and names the words; that cannot happen with the samples shipped, which the tests build one by one.

### Importing
| command | arguments | result |
|---|---|---|
| `backup.dir` | `dir` (a folder, or null or empty for beside the project), `check` (default true) | `{dir}`. The folder where backups go, for the open project and every project opened after it. A folder that is not there, is a file, or cannot be written in (a probe file is made and removed) is `invalid` with its reason and nothing changes; `check: false` hands over a folder without refusing it (the interface does this once at start-up for a folder saved earlier). Each project gets its own folder inside it, named for the project and the start of its identity, so two projects with the same file name never share backups. If the folder cannot be used when a backup is made, the copy is made beside the project instead and `project.backup` says so in `note` |
| `import.inspect` | `path`, `name`, `folder`, `source_type`, `unit_kind`, `interviewers[]`, `mapping`, `social_mapping` | for a document: `{kind: "batch", duplicate_of, summary}`. For a spreadsheet: `{kind: "table", duplicate_of, table, warnings, suggested_mapping, summary}` where `table.columns[]` has `name, label, guessed_level, looks_like, distinct, empty, mean_words, samples[], suggested_role`; `summary` is null until a `mapping` is sent |
| `import.run` | the same, plus `force` | `{outcome: {source_ids, case_ids, units_created, attribute_values_created}, summary}` |
| `import.revise` | `source_id` (the document), and the same file choices as `import.run` (`path`, `source_type`, `unit_kind`, `interviewers[]`) | `{outcome: {text_revision, characters, codings_moved, codings_removed, units_moved, units_removed, units_added, proposals_rejected}, summary, backup, backup_note}`. Takes the file as the new version of a document already in the project: it stays the same document (same number, name, case, attributes, memos, and codings), its text becomes the file's text, and every coding, unit, and format run follows the words that survive, exactly as in `source.edit`. The file's own formatting replaces the old, `original_file_hash` becomes the file's, and units the revised text has that the document had none for (a new speaker turn) are added (`units_added`); units that overlap one the document kept are not. A backup copy of the project is saved first (`backup`). Logged as `source.revise`, with every removed coding in full; `undo` cannot take it back (`invalid`, saying so), the backup is the way back. `invalid` for a spreadsheet or any file that makes more than one document, for the file the document came from, and for a file with no text; `not_found` for a document that does not exist |

Kinds of file `import.inspect` and `import.run` read, by the file's ending: text, Markdown, HTML, Word, OpenDocument text, RTF, PDF, transcripts (`.vtt`, `.srt`), spreadsheets and SPSS files (these give a table), social media exports (`.json`), and, from format 3 on:

- **Reference libraries**: RIS (`.ris`), BibTeX (`.bib`, `.bibtex`), and CSL JSON (a `.json` list of items that each have a `type` and a title or authors; a Reddit export is not mistaken for one). Each reference is one source, filed in the folder `References`, whose text is its title, details, abstract, and keywords, and one case named for it whose variables are Authors, Year (interval), Published in, Reference type (nominal), DOI, and Keywords. A reference with no abstract carries the warning `no_abstract`.
- **E-mail**: one message (`.eml`) or a mailbox (`.mbox`, up to 20,000 messages). Each message is one source, in the folder `Email`, with its From, To, Cc, Date, and Subject lines above its text (the plain text part, or the HTML part when there is none; attachments are not read and are named in the warning `skipped_attachment`), and one case with the variables From, To, Date (date), and Subject.
- **Saved web pages**: a page a browser saved whole (`.mht`, `.mhtml`) gives one source in `Web pages` and a case with Title, Address, and Saved. Plain `.html` files are read as before.
- **News feeds**: RSS or Atom saved as a file (`.rss`, `.atom`, `.xml`). Each item is one source in `News` with a case holding Title, Published, Author, Link, and Feed. Other XML is refused as `unsupported_file`. Custom entities are never expanded.

Nothing is fetched from the internet: there is no command that takes an address. In `summary.sources[]`, `format` says which of these a source came from (`ris`, `bibtex`, `csl-json`, `eml`, `mbox`, `mhtml`, `feed`) and is null for every other kind.
| `import.folder` | `path` (a folder), `recursive` (true), `folder` (a folder name to file everything under), `source_type`, `unit_kind`, `interviewers[]`, `include_tables` (false), `force` | `{imported: [{path, source_ids, units}], duplicates: [{path, message}], skipped: [{path, reason}], failed: [{path, code, message}], sources_created, units_created}`. Imports every readable file one at a time, each in its own transaction, so a file that cannot be read is reported and the rest still go in. Subfolders become folders of sources. Spreadsheets and SPSS files are skipped unless `include_tables` is true, because they need their columns set up. Word's `~$` lock files and hidden files are ignored |

A `mapping` is `{id_column, unit_id_column, text_columns[], attribute_columns[{name, level}], unit_attribute_columns[{name, level}]}`. A `summary` is `{sources: [{name, source_type, characters, units, default_unit_kind, format_runs, warnings[{kind, message, location}]}], cases, case_attributes}`.

Undo removes an added case only while it is still empty (no sources, memos, or attribute values); after that it says so with the code `invalid`.

**What a run takes.** `method: "words"` takes `query` (the language below), `target` (`hit`, the matched words, which is the default; `words`, with `around` from 1 to 50 words each side, never past the start or end of the unit or paragraph the match was found in; `sentence`; `paragraph`; or `unit`), and `limit` (at most 20,000 places). `method: "speakers"` takes `speakers: [{key, code_id | new_code}]`, keys from `autocode.speakers`; every turn of those speakers that is not left out of coding is suggested, tied to its unit. `method: "headings"` takes `levels` (1 to 6), `heading_query` (the same language, applied to the heading's own words), and `include_heading` (default true); a section runs from its heading to the next heading of the same or a higher level, and sections that overlap are joined. **What a run leaves out.** A suggestion is not queued when the same coder has already given that code to all of those words, or when the same suggestion already waits; both are counted in the answer. Each queued suggestion's note says how it was found (`autocoded from search: cost`, `autocoded from speaker: Priya`, `autocoded from heading: Findings`) and becomes the coding's note when it is accepted.

The query language: `cost` (a word), `"first day"` (a phrase), `welcom*` and `wom?n` (wildcards), `/regex/`, `AND` `OR` `NOT` (capitals), parentheses, and `cost NEAR/5 access`. Booleans are decided inside one unit, or one paragraph when the source has no units.

### Pictures and coded areas

A picture is a document: its `text` is a description (what a screen reader speaks for it), and the picture itself, byte for byte as the file was, is kept inside the project file (format 7, `image` table). A coded area is one code given to one area of one picture by one coder, kept in its own table (`region`) beside `coding`, because a coding is a stretch of text counted in characters and an area is a shape counted in fractions of the picture. Every coordinate is a fraction of the picture as it is shown (turned upright by a camera's own turn marker): 0 is the left or top edge, 1 is the right or bottom edge. Numbers are rounded to five decimals, so two areas with the same shape read as equal.

A shape is `{shape: "rectangle", x, y, w, h}` (top left corner and size), `{shape: "ellipse", x, y, w, h}` (the ellipse that fits the box), or `{shape: "polygon", points: [[x, y], ...]}` (3 to 500 corners, filled by the even-odd rule). A rectangle or ellipse is at least 0.2% of the picture along each side; a polygon must enclose some ground and stay inside the picture.

Add a description of what it shows.", with one paragraph unit, `source_type` `other`, and the file kept in the project. `summary.sources[].format` is `image`. The size is the size as shown (a JPEG's camera turn marker is applied, so a photograph taken upright on its side is read the right way up). A TIFF, HEIC, AVIF, or camera raw file is refused as `unsupported_file` with the words "Save NAME as a PNG or JPEG and import that"; a file whose bytes are not the kind its ending says, one over 64 MB, and one over 30,000 pixels on a side are refused as `format` with the reason. `import.revise` refuses a picture |

### Pseudonymizing and redacting
One list of things to find and what takes their place (decision 156, project format 13: the table `deid_rule` and the switch `project.deid_exports`). ### Encrypted projects
Decision 157. An encrypted project is a SQLite file with every page encrypted (SQLite3 Multiple Ciphers, SQLCipher 4 compatible: AES-256-CBC, an HMAC-SHA512 on each page, PBKDF2-HMAC-SHA512 at 256,000 rounds), so it does not begin with `SQLite format 3`. A passphrase has at least eight characters, is put in Unicode NFC, is not only spaces, and cannot begin with `x'`. Nothing about it is stored: a lost passphrase cannot be recovered. `project.info` has `encrypted`. These commands never write a passphrase to the audit trail (`project.encrypt`, `project.decrypt`, and `project.passphrase` record only that it happened, with the cipher in words, and `undo` walks past them).

| command | arguments | result |
|---|---|---|
| `project.create` | the usual, and `passphrase` | a project encrypted from the start. `invalid` (with the reason) for a passphrase that is too short or would be misread; nothing is made |
| `project.open` | the usual, and `passphrase` | An encrypted file opened without one is `needs_passphrase`; with a wrong one, `wrong_passphrase` (also what a file that is not a project at all says when it could be encrypted). A passphrase given for a project that is not encrypted is ignored |
| `file.stat` | `path` | adds `encrypted`: whether the file begins like an encrypted project (only its first bytes are read, and no `-wal` file appears) |
| `project.encrypt` | `passphrase` | `{encrypted, old_file_erased, stale_backups, backup_folder, cipher, info}`.
