# Design decisions made while building

The specification ([SPECIFICATION.md](SPECIFICATION.md)) says what PrismQDA does. This file records choices the specification left open and that the code now depends on, so they can be reviewed and changed on purpose. Each says where to change it.

## 2026-11-04: first scaffold of the engine

| # | Decision | Why | Where to change it |
|---|---|---|---|
| 1 | Text offsets count Unicode scalar values (code points) of the source's NFC text. Start is inclusive, end is exclusive. | The specification does not say. Counting code points never splits a character, is the same whatever the file's encoding, and is simple to explain to anyone who reads the database with R or Python. The Tauri interface works in UTF-16 units and will convert at the boundary. | `schema/v1.sql` header comment; `check_span` in `ops.rs`; `source.char_count` |
| 2 | The project file extension is `.pqda`, provisional. | The extension is an open question (specification section 30). One constant keeps it easy to change. | `PROJECT_EXTENSION` in `project.rs`; `.gitignore` |
| 3 | The license checker is written fresh in Rust (`tools/prismqda-licensecheck`), not copied from another project. | Whether to copy code from the author's other projects is still an open question. Writing it in Rust also keeps Python out of the build. | `tools/prismqda-licensecheck` |
| 4 | The event log is append-only inside the database itself, with triggers that refuse UPDATE and DELETE. | Specification 14.1 says entries cannot be edited or deleted. A trigger holds even for a tool that opens the file without the engine. | `schema/v1.sql`, end of file |
| 5 | Backups go in `<project name>.backups/` beside the project, named `<name>-<UTC time>-<nn>.pqda`, and are ordinary project files. The command-line harness does not back up on open unless asked; the desktop app will. | Specification 4.1 asks for a backup on open, every 15 minutes, keeping 10. The engine provides `backup_now` and `keep_backups`; the 15-minute timer belongs to the app. | `Project::backup_now` |
| 6 | Version 1 of the schema is one full file. Later versions are added to `MIGRATIONS` as SQL steps, and `schema/` will keep the current full schema beside them. | Keeps the published schema readable as a whole. | `schema.rs` |
| 7 | Active codes under the same parent cannot share a name, ignoring case. | Stops accidental duplicates from in-vivo coding. Not in the specification; remove if it gets in the way. | `Project::add_code` |
| 8 | A model coder must name its model. | Specification 9.4 says every report names each coder's model and version. | `Project::add_coder` |
| 9 | In unit mode a coding must have a unit, and its span must lie inside that unit. Excluded units cannot be coded. | Specification 7.2 and 5.1: content analysis requires unit mode; interviewer turns can be excluded. | `Project::apply_coding` |
| 10 | The table for cases is `research_case`. | `case` is a reserved word in SQL and makes queries from R and Python awkward. | `schema/v1.sql` |
| 11 | SQLite is built into the program (the `bundled` feature of rusqlite) rather than loaded from the system. | The program must run on a clean Windows install with nothing else on it. SQLite is public domain, noted in NOTICE. | `crates/prismqda-engine/Cargo.toml` |

## 2026-11-04: importers, search, text edits, and agreement

| # | Decision | Why | Where to change it |
|---|---|---|---|
| 12 | A spreadsheet becomes sources, cases, and attributes through a `SurveyMapping`: one column can name the case, one the unit's own identifier, any number hold the text, and any number become attributes of the unit (or the case). Each text cell becomes one unit; the unit keeps its identifier so coded files can be matched back to it. | Specification 5.1 and 8.1 describe the result but not the mapping. Keeping the identifier is what lets a second coder's file be imported later. | `crates/prismqda-import/src/table.rs` |
| 13 | The SPSS `.sav` and `.zsav` reader is written in Rust and checked against R's `haven` on fixtures. ReadStat and SQLCipher are not used. | Keeps the build free of C code with unclear licences, and keeps the licence rule simple. | `crates/prismqda-import/src/sav.rs` |
| 14 | When text is edited, codings keep the characters that survive. A word that was corrected (at least half the same) survives whole. A coding whose text was deleted is removed, and the removal is logged in full so nothing is lost silently. The match runs lines, then words, then letters, choosing the alignment that keeps the most matched text. | Specification 4.3 asks that edits not destroy coding. The rule had to be exact enough to test with random edits. | `crates/prismqda-engine/src/edit.rs` |
| 15 | Search decides AND, OR, NOT, and NEAR inside one unit, or one paragraph when a source has no units. The text is scanned once per source, not once per term. | Specification 6 does not say what "together" means; the unit is the thing being coded. Scanning once is what keeps a 25-million-word project inside the specification's time limits. | `crates/prismqda-engine/src/search.rs` |
| 16 | Autocoding and model suggestions go to a review queue and change nothing until a person accepts them. | Specification 7.5 and 10. | `crates/prismqda-engine/src/proposal.rs` |
| 17 | Undo reaches back only through changes the person made in this session, stops at a change that cannot be reversed safely, and says so. A reliability run or its archiving is a record, not an edit, so it never blocks undo. | An undo that silently skips steps is worse than none. | `crates/prismqda-engine/src/undo.rs` |
| 18 | Agreement statistics are checked against R (`irr` 0.85, `irrCAC` 1.4) on the same tables. The plain-R definitions must match to 1e-12, `irr` to 1e-9, and `irrCAC`, which rounds to five decimals, to 6e-6. | One tolerance for all would either hide real differences or fail on rounding. | `crates/prismqda-stats/tests/agreement_reference.rs` |
| 19 | Where `irr::kripp.alpha` and the definition of Krippendorff's alpha disagree (one test table, 0.300398 against 0.302347), PrismQDA follows the definition. The definition was worked in exact fractions separately, and `irrCAC` agrees with it. The test pins the disagreement so a change in `irr` is noticed. | A coefficient that matches a package but not its own definition cannot be defended in a methods section. | `crates/prismqda-stats/src/agreement.rs`, the last test of `agreement_reference.rs` |
| 20 | Agreement counts units that at least two coders rated. Observed agreement is the average, over those units, of the share of matching pairs. A coder with no coding on a unit has not rated it; this is not the same as rating it "not applied". Cohen's kappa uses units both of two coders rated; Fleiss' kappa uses units every coder rated. | Specification 9 does not say how a unit one coder skipped is treated. Counting it as "not applied" would reward a coder for skipping hard units. | `crates/prismqda-stats/src/agreement.rs`, `crates/prismqda-engine/src/reliability.rs` |
| 21 | Agreement is measured on each coder's own codings only, never the adjudicated final layer. A coding belongs to a unit by its unit identifier, or by lying wholly inside the unit when it has none. | Specification 9.5: the adjudicated layer is the result of resolving disagreement, so measuring it would measure the resolution. | `Project::codes_by_unit` |
| 22 | Two views of agreement. `single_label` (one code per unit, as in content analysis) gives every coefficient, a confusion table for two coders, and a bootstrap interval. `per_code` (each code applied or not) gives the coefficients per code with prevalence, bias, and PABAK. A unit with more than one code from a coder is refused in `single_label` with a message that points to `per_code`. | The two designs answer different questions, and mixing them gives numbers that look right and mean nothing. | `Project::agreement_run` |
| 23 | A run that includes a model coder is called "concordance" unless the person picks the other word, in which case the report says why most people do not. Two or more model coders add a line that models may share training data and habits. | Specification 9.4: say what was measured. Agreement with a model is not reliability between independent judges. | `notes_for` in `reliability.rs` |
| 24 | The report warns when percent agreement is 0.80 or more but the chance-corrected coefficient is below 0.60, or (per code) when agreement is 0.90 or more and alpha is below 0.60. The warning names Gwet's AC1 and the Brennan-Prediger coefficient as the measures less affected by a dominant code. | The "kappa paradox". The report should explain it, not leave a reader thinking the coding is bad or good. | `notes_for` |
| 25 | The bootstrap resamples units with replacement, 1,000 times by default, and reports a 95 percent percentile interval. Samples and bootstraps use SplitMix64 with a seed that is saved in the run, so the same seed gives the same answer on any computer. | Reproducibility; the standard library has no random numbers and a package would be one more dependency to audit. | `crates/prismqda-stats/src/rng.rs` |
| 26 | A random sample is a partial Fisher-Yates shuffle. A stratified sample gives each group its share by the largest-remainder rule, so group sizes always add up to the sample size. Units left out of coding are never drawn. | Simple, exact, and easy to explain in a methods section. | `Project::draw_sample` |
| 27 | A saved run locks the text of every source that has one of its units until the run is archived. Archiving keeps the run and its report. | Specification 4.3: the agreement reported must match the text it was computed on. | `Project::reliability_lock`, `replace_source_text` |
| 28 | The project's agreement target is 0.80 (Krippendorff's alpha) and the report says which codes fall under it. | Specification 9.3. Change it per project in the `project` table. | `agreement_target` in `schema/v1.sql` |
| 29 | Five crates under the Mozilla Public License 2.0 (`cssparser`, `cssparser-macros`, `dtoa-short`, `selectors`, `option-ext`) are accepted as reviewed exceptions to the license rule. Each is matched by name and exact license text, so a new version that changes its license is held for review again. They are written up in THIRD-PARTY.md, which the installer carries. **Reviewed and kept by the author, 2026-11-07** ("it makes sense to keep them"). The specification's rule says "permissive licenses only" and blocks GPL, LGPL in static builds, AGPL, and non-commercial licenses. MPL-2.0 is none of those, but it is weak copyleft, so it is not quite "similar permissive". | They arrive with Tauri, which the specification chooses for the window. MPL-2.0 covers the files of the library, not the program that uses it, and the five are used unmodified. The alternative is to drop Tauri for a plain `wry` window, which has the same drawbacks plus more work. | `REVIEWED` in `tools/prismqda-licensecheck/src/lib.rs` |
| 30 | The desktop app (`app/src-tauri`) is its own Cargo workspace with its own lock file, not a member of the engine's. The licence check and THIRD-PARTY.md cover both. | Tauri adds about 470 crates. In the engine's workspace they would be rebuilt by every `cargo test --workspace`, and the engine would sit beside a window toolkit it does not need. | `app/src-tauri/Cargo.toml`, `manifests_under` in the license checker |
| 31 | The window talks to the engine through one Tauri command, `call`, the same `Api::call` the tests and the development bridge use. The person's name on every change is their Windows account name until the interface lets them set one. A backup runs every 15 minutes while a project is open. | One door means the interface is tested against exactly what ships (specification 3.2). The 15-minute backup is specification 4.1; the engine already backs up on open. | `app/src-tauri/src/main.rs` |
| 32 | The installer is NSIS, per user (no administrator rights); unsigned until alpha 53, signed from alpha 54 (decision 184). | Windows will show a SmartScreen warning for an unsigned installer. Signing costs money or needs the public repository for SignPath, so it waits for the first public release. | `app/src-tauri/tauri.conf.json` |
| 33 | The icon is a prism seen end-on in three colored facets, drawn by `app/src-tauri/icons/make_icons.py` with no packages. A first version, a beam of light split into a rainbow, was dropped because it too closely resembled a famous album cover. | A placeholder that is original and easy to regenerate. Replace with a designed icon before a public release. | `app/src-tauri/icons/` |
| 34 | The exporters write Excel, Word, CSV, and QDC themselves, with no library for any of them. | These are small, fixed formats. Writing them directly adds nothing to audit, and each is tested by reading the file back, and the Word and Excel files were also opened in real Word and Excel (hidden) and read back correctly. | `crates/prismqda-export` |
| 35 | An export never replaces an existing file unless the request says so (`overwrite`). A path typed into the interface never does; a path chosen in Windows' own save dialog, which has already asked, does. Files are written beside the target and renamed. | A typed path is easy to get wrong, and a half-written file under the real name is worse than none. | `write_export` in `crates/prismqda-api/src/lib.rs` |
| 36 | CSV files start with a byte order mark so Excel reads them as UTF-8, and text that starts with `=`, `@`, a tab, a carriage return, or a `+` or `-` that is not a number gets a leading apostrophe so a spreadsheet does not run it as a formula. | Coded text comes from participants; a comment that begins with `=` must not execute. | `crates/prismqda-export/src/csv.rs` |
| 37 | The QDC export writes the REFI-QDA codebook structure (a `CodeBook` element in the `urn:QDA-XML:codebook:1.0` namespace, nested `Code` elements with `guid`, `name`, `isCodable`, `color`, and a `Description`). A theme is not codable. A code's inclusion and exclusion criteria are added to its description, because the format has no field for them. Identifiers are derived from the project's identifier and the code's number. **It was written from the published structure and has not been checked against the official schema or opened in another program.** | Specification 17. Stable identifiers mean exporting twice, or importing elsewhere and back, does not duplicate codes. | `crates/prismqda-export/src/qdc.rs`, TESTING-TODO.md |
| 38 | Importing a folder takes every readable file one at a time, each in its own transaction, and skips spreadsheets and SPSS files unless asked, because each needs its columns set up. ## Known limits

- A project is one file only while it is closed. While it is open, or after the program was killed rather than closed (Task Manager, a power cut), the newest work can sit in a `-wal` file beside it. Opening the project in place always recovers it; the dated backups in the `.backups` folder are complete single files. Copy a project only after closing it.

- An attribute whose type differs between two imports (a column read as a date in one file and as text in another) is refused by the engine rather than converted. The person fixes the column type in the import dialog.
- Reddit posts are stored as the root of their thread, and the YouTube importer estimates a comment's date from the "3 weeks ago" text that `yt-dlp` records. Both should be confirmed against a real export.
- The desktop shell (Tauri) and the React interface are not part of the engine; the interface is built against the command layer in [API.md](API.md).
- Queries, matrices, and QDPX exchange (milestones 2 and 3), adjudication, and the writing tools are not started. AI is built only as prompt packets (decisions 91 to 95); no model is ever called. Screens for reliability runs do not exist yet (the engine and command layer do). [ROADMAP.md](ROADMAP.md) has the order.
